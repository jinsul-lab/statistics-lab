# 경쟁 의원 분류 API 검토 — v3.7.7

확인일: **2026-09-30 (Asia/Seoul)**. 저장 표본의 최초 조회 시각은 `2026-09-29T15:17:07.2257107Z`이며 각 기관의 `checkedAt`을 별도 보관했다. 공식 명세·공개 API 표본·모의 회귀 검증과 실제 브라우저 조회 결과를 구분하여 기록한다.

## 적용 기준

경쟁병원은 **의원 종별 `31` + 선택한 대상 과 전문의 신고 1명 이상 + 입원 병상 0 확인**을 모두 만족하는 기관이다. 대상 과 코드는 정형외과 `05`, 신경외과 `06`, 마취통증의학과 `09`, 재활의학과 `21`이다.

입원 병상이 있는 의원은 제외한다. 입원 병상 0이 확인되고 선택 과 신고는 있으나 해당 전문의가 없으면 **심평원 신고의원**으로 남긴다. API 실패, 전체 응답 미확인 또는 필수 값 누락은 **분류 확인 필요**이며 경쟁 수에 넣지 않는다.

[공공데이터포털 의료기관별상세정보서비스](https://www.data.go.kr/data/15001699/openapi.do)의 내장 Swagger를 2026-09-30 확인했다. 서비스 경로는 `B551182/MadmDtlInfoService2.8`이다.

| 목적 | Operation | 판단 필드 |
|---|---|---|
| 전문과목별 전문의 수 | `getSpcSbjtSdrInfo2.8` | `dgsbjtCd`, `dgsbjtCdNm`, `dtlSdrCnt` |
| 신고 진료과목 | `getDgsbjtInfo2.8` | `dgsbjtCd`, `dgsbjtCdNm`, `dgsbjtPrSdrCnt` |
| 시설·병상 | `getEqpInfo2.8` | 아래 병상 필드 |
| 의료장비 | `getMedOftInfo2.8` | `oftCd`, `oftCdNm`, `oftCnt` |
| 특수진료 가능 분야 | `getSpclDiagInfo2.8` | `srchCd`, `srchCdNm` |

기존 `getSpcSbjtSdrInfo2.8`는 올바른 전문의 API다. `dgsbjtPrSdrCnt`의 Swagger 설명은 의사수이므로 단독 전문의 판정값으로 대체하지 않는다. 신고 과목명 또는 의원 이름에 특정 진료과가 있는 것만으로도 전문의 보유를 추론하지 않는다. JSON 과목 코드는 문자열과 숫자가 혼용되어 두 자리 문자열로 정규화한다.

입원 병상 판단 필드:

```text
permSbdCnt
hghrSickbdCnt, stdSickbdCnt
aduChldSprmCnt, chldSprmCnt, nbySprmCnt
psydeptClsHigSbdCnt, psydeptClsGnlSbdCnt
psydeptOpenHigSbdCnt, psydeptOpenGnlSbdCnt
isnrSbdCnt, anvirTrrmSbdCnt, dtrmSbdCnt
```

`permSbdCnt`는 허가병상수이고, 상급·일반 입원실, 중환자실, 정신과 입원실, 격리실·무균치료실과 겹칠 수 있다. 따라서 허가 합계와 세부 병상을 더하지 않는다. 어느 입원 항목이든 양수면 제외하고, 필수 항목 전체가 명시적 0일 때만 입원 병상 0을 확인한다. 신규 항목 `dtrmSbdCnt`는 명세상 임종실로, 보수적으로 이 확인에 포함한다.

`ptrmCnt`(물리치료실), `soprmCnt`(수술실), `emymCnt`(응급실), `partumCnt`(분만실)는 이 입원 판단에 더하지 않는다. HIRA의 [2025년 공식 자료](https://www.hira.or.kr/ebooksc/2025/12/BZ202512182687663.pdf)는 일반·정신과 입원실, 중환자실, 격리실·무균치료실을 입원 병상으로, 물리치료실·수술실·응급실·분만실 등을 특수진료실 병상으로 구분한다.

## 정상 0과 미확인의 구분

- 시설 표본 전부에서 0인 병상 필드도 실제로 반환됐다. 빈 값이나 누락을 숫자 0으로 바꾸지 않는다.
- 전문의가 없는 의원 3곳은 정상 코드 `00`, `totalCount: 0`, `items: ""`를 반환했다. 이 정상 완료 응답은 신고 전문의 0이다.
- 정상 완료 전문의 목록은 해당 기관의 보유 전문과목을 반환했다. 전체 목록에서 선택 과가 없으면 그 과 전문의 신고 0으로 처리한다.
- 정상 코드뿐 아니라 전체 건수와 수신 행 수의 일치도 확인한다. 결과가 없다는 뜻과 조회에 실패했다는 뜻을 구분한다.
- 동일 코드의 상충 수치, 잘못된 수치, 전체 건수 누락이나 일부 페이지만 받은 상태는 확인된 0이 아니다.

## 해석 한계

[병원정보서비스 설명](https://www.data.go.kr/data/15001698/openapi.do)은 요양기관이 심평원에 신고한 자료를 기준으로 한다고 명시한다. 전문의 수에는 당일 근무 시간표나 상근·비상근을 판별하는 차원이 없다. 화면 문구는 **전문의 신고 확인**으로 두고 현재 상주나 당일 근무 확인으로 표현하지 않는다.

이 API는 병상 수를 제공하며 입원실 방 개수의 독립 필드를 제공하지 않는다. 따라서 확인 가능한 표현은 **입원 병상 0**이다. 이번 열 기관은 분류 규칙 검증을 위한 표본이며 전국 자료의 완전성이나 기관의 현재 실제 운영 상태를 보증하지 않는다.

## 앱 반영 범위

- 상권 스캔의 경쟁 수·거리·밀도·진료과별 그래프·후보지 비교·마커는 확인된 경쟁의원만 사용한다.
- 심평원 신고의원은 별도 목록·마커로 제공한다. 분류 확인 필요·분석 제외는 이유를 표시하며 경쟁 집계에 합산하지 않는다.
- 카카오 이름/진료과 검색은 접힌 참고 목록으로 보존하며 전문의 보유 근거로 사용하지 않는다.
- 환자 화면의 경쟁의원 시설 검색도 같은 API와 기준을 사용한다. 5km를 넘는 화면 범위는 확대 안내를 제공한다.
- 입지자료 기본 경쟁 목록·통계·저장·불러오기·출력에 분류 근거를 유지한다. 타과 포함 모드는 신고기관 참고로 명시하고, 과거 저장자료는 재조회 필요로 표시한다.
- 입원 병상 보유 의원의 제외는 사용자가 지정한 입지 분석 규칙이며 법적인 1차/2차 의료기관 판정이 아니다.

## 실제 브라우저 및 API 조회

현재 HTML을 로컬 HTTP로 실행하여 **경기도 시흥시 정왕대로 210, 반경 500m, 대상 4개 과 전체 선택**으로 실제 조회했다. 모의 응답을 주입하지 않았다.

| 분류 | 기관 수 |
|---|---:|
| 경쟁의원 | 3 |
| 심평원 신고의원 | 3 |
| 입원 병상 보유로 제외 | 5 |
| 분류 확인 필요 | 0 |

조회된 심평원 진료과 신고기관 11곳 중 경쟁의원은 시흥고려튼튼의원(재활 1명), 박동원재활의학과의원(재활 1명), 서울바로마취통증의학과의원(마취통증 1명)이었다. 세 기관 모두 필수 입원 병상 항목 0을 확인했다. 카카오 참고 검색 9곳은 경쟁 수에 합산하지 않았다.

지도 요약·종합 진단·진료과별 그래프 및 입지자료 표에 같은 경쟁 3곳이 표시되는 것을 확인했다. 입지자료 표의 해당 전문의 수와 입원 병상 0 표시도 확인했다. 사용자 기존 저장자료에 시험 자료를 저장하지 않았다. 이는 조회 당시의 특정 반경 결과이며 시흥시 전체 기관 수가 아니다.
