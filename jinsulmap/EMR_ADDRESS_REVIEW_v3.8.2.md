# 의사랑·비트 환자 주소 감사 · JINSUL MAP 3.8.2

2026-10-04. **Share with caveats / Partial**. 데이터 전문가·통계 전문가 독립 검토 후 지원되는 결함을 수정했다. 실제 의사랑·비트 내보내기 원본이 제공되지 않아 공급사별 공식 스키마, 실제 ‘미상’ 비율, 대량 실제 API 성공률을 확인한 것은 아니다. 공급사 이름을 근거 없이 자동 확정하지 않고 열 구조를 해석한다.

## 확인된 원인과 수정

1. **주소 열 선택·결합 오류.** 기존에는 첫20행에서 ‘주소’가 처음 나오는 행을 헤더로 삼고 주소가 들어간 첫 열 하나만 사용했다. 안내문·상세주소·직장/보호자주소가 먼저 나오거나 기본/상세가 분리되면 환자 거주지를 놓칠 수 있었다. 수정: 환자 고유번호와 주소 구조를 함께 탐색(첫100행), 주소가 있는 환자 시트를 우선, 거주 주소 우선순위·빈 도로명 뒤 지번 대체·지역/도로명/건물번호 결합. 주소2가 명백한 전체 주소면 회복한다. 상세 호실만으로 위치를 추정하지 않는다. 인식한 열을 화면에 표시하고 직접 지정해 재분석할 수 있다.
2. **결측·식별자 포맷 오류.** ‘미상’ 첫 주소가 뒤 유효 주소를 막고, 환자번호가 이름으로 선택되며, CSV/XLSX에서 차트번호 앞0이 없어질 수 있었다. 수정: 결측 표기 정상화, 정확한 이름 열, CSV 문자열 보존·XLSX 표시서식 보존, UTF8/CP949/UTF16 BOM 처리. 서로 다른 유효 원주소는 보존하고 첫 유효 주소 정책을 유지하며 충돌 수를 안내한다. 현재 자료에 방문일 우선 정책을 새로 만들지 않는다.
3. **주소 없음·검색 실패·대기 상태 혼합.** 기존에는 환자마다30ms 간격으로 조회하고 실패 사유 없이 미상으로 집계했다. 수정: 같은 원주소 요청 통합, 주소 작업자 최대3개·시작150ms 간격, 응답8초 제한·API 오류1회 재시도. 원주소 없음/처리 중/검색 불일치/조회 실패/다중 후보/번지·건물번호 부족/좌표 확인 상태를 분리한다. 오류 상태는 성공 캐시로 고정하지 않으며 명시적으로 다시 조회할 수 있다. 작업 중 재조회는 막고 새 업로드·초기화는 이전 결과 적용을 취소한다. SDK 요청은 물리적으로 중단할 수 없어 시간초과 후 재시도가 실제 네트워크 동시3개를 항상 보장하지는 않는다.
4. **반경 미확인 수와 마커 의존 집계.** 기존에는 무좌표 환자가 반경 필터에서 제외된 뒤 ‘좌표 미확인0명’으로 보이고 클러스터가 감춘 개별 마커 때문에 반경 인원이 달라질 수 있었다. 수정: 유형 필터 적용 후, 반경 적용 전 집단의 주소 상태를 공개하고 반경 분석에서 제외한 무좌표 인원을 별도 안내. 반경 인원은 좌표·선택 유형·직선거리로 계산하며 마커 표시 여부에 의존하지 않는다. 미확인 환자를 반경 밖이라고 판단하지 않는다.
5. **지역 필드 유실·행정동/법정동 혼합.** 도로명 응답만 있으면 지역이 사라지고 행정동과 법정동을 같은 동처럼 집계할 수 있었다. 수정: 행정동 우선, 필요하면 좌표의 행정동 조회. 확인 불가 시 법정동은 `(법정동)`을 붙여 별도 집계하며 도로명 응답도 사용한다. 동 미확인과 좌표 미확인은 다른 지표다.

## 범위와 해석

- 원본 환자·기록 수, 신환/90일 분류, 연령 계산, 반경 포함 경계와 직선거리 정책은 유지했다. 확인된 주소가 늘면 지역/거리 분포는 실제로 달라질 수 있다.
- 원주소와 변환 질의는 페이지 메모리에 유지하며 환자 행·주소를 Git, 테스트 보고서, 서버 로그에 저장하지 않는다. 주소 변환은 기존처럼 카카오 주소 API를 사용한다.
- 우편번호·괄호·상세 호실을 정리하되 번지/도로명 건물번호를 유지한다. 넓은 동/구 주소를 중심점으로 환자 위치처럼 찍지 않는다. 서로 다른 좌표 후보가 있으면 첫 후보를 임의 선택하지 않는다.
- 원본이 불완전하거나 오래된 주소, 오타·이사·동명이인 주소는 원자료와 대조해야 한다. 이름이나 전화번호로 환자를 합치지 않는다.
- 사용 방법: 환자 파일 업로드 → ‘주소 열’ 안내 확인 → 잘못 인식되면 기본/상세 열 직접 지정 → 처리 완료 상태 확인 → 일시 실패는 ‘미확인 주소 다시 조회’. 타입/반경 필터 아래의 상태 집단을 구분해 해석한다.

## 검증 증거

- 수정 전 a5dee1f: 데이터 전문가 합성 실패13개, 통계 전문가 별도 결함 재현. 재현 스크립트는 Git에서 당시 HTML을 읽으며 최신 회귀 성공 검사와 구분한다.
- 최신 `test_emr_address_import_v382.cjs`:28개 성공. 실제 SheetJS0.18.5로 합성 XLSX/CSV/UTF16 TSV, 앞0·시트 우선·열 결합·결측 회복·충돌·직접 지정·동일 기록 정책 검사. API는 호출하지 않았다.
- 최신 `test_emr_geo_v382.cjs`:49개 성공. API 모의 응답으로 요청 통합/동시 작업/시간 초과/재시도/새 업로드/상태/법정동 표시/반경 분모와 마커 독립 집계를 검사.
- 통계 독립 참조: 합성8명·14기록, 좌표 확인4명(50%), 1km내3명, 확인된 밖1명, 판정 불가4명. 확인 집단의 반경내 비율3/4=75%와 전체의 확인된 반경내 비중3/8=37.5%를 혼동하지 않는다. 평균거리550m·중앙300m; 전체 신환 반복기록4/6=66.7%, 반경내1/2=50%.
- `test_emr_address_ui_v382.cjs`: 실제 작성한 컨트롤과 합성8명·모의 API를 오프라인 브라우저에서 렌더. 좌표3명·각 미확인 상태 표시, 주소 열 선택,44px 선택 영역, desktop1280 및 tablet768 화면 스크린샷 직접 확인. 실제 연결된 전체 앱 화면이나 공공 API 실측 검증을 대신하지 않는다.
- 기존 환자 실제 Chart.js 전체 탭/산점도/빈값/필터·태블릿 렌더, 기록/연령/거리 참조, 파일 읽기 경합, 게시대 묶음/구문 검사, 의원 기준159·통합69·노인시설204 모의 검사 통과. 통합 검사에 누락됐던 비교 안내 함수 로딩을 보완했다.
- 실제 브라우저 제공자가 없어서 이번 턴 실제 카카오 지도/API UI 검증은 불가했다. 실제 EMR 표본은 사용자에게 열 제목·가린 형식 예시로 요청했으며 아직 미제공이다. 전체 공급사 호환·전국 주소 성공을 확정하지 않는다.
