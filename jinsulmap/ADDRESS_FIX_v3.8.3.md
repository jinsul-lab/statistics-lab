# 실제 XLS 주소 조회 회귀 수정 · v3.8.3

2026-10-24. 기준 소스: 3.8.2 `7e35b09`, 비교 소스: Git `020b3b1:JINSUL_MAP_v3.2.0.html`. 실제 파일은 사용자 지정 로컬 XLS를 메모리에서 읽었다. 파일·원본 행·환자명·번호·주민번호·전화·실주소·좌표를 저장소에 넣지 않았다.

## 결론

파일 해석 실패가 아니라 **주소 API 검색 옵션의 잘못된 값과 지도 표시 지연**이 주된 회귀였다. 이전 3.8.2 수정에서 `analyze_type:'EXACT'`를 보내 실제 카카오가 HTTP400으로 거절했다. 허용 값은 소문자 `exact`·`similar`다. 3.2.0은 이 옵션을 직접 지정하지 않아 기본 검색이 작동했다. 모의 응답 검사는 대문자를 거절하지 않아 이 결함을 놓쳤으며, 실제 API 계약 검사와 잘못된 대문자로 되돌린 변이 검사를 추가했다.

수정 전 공개 건물4개: 좌표0·API실패3·번지형식 차단1. 실제 응답 본문은 `ValidationError`, `query.analyze_type`, `should be one of exact, similar`였다. 수정 후 같은 공개4개는 모두 좌표·동 확인. 사용자가 별도 허용한 실제 주소30개 표본도30/30 확인됐다. 이는 표본 성공이며 전체 주소 성공률·좌표 정답률100%를 뜻하지 않는다.

## 수정 내용

1. **실제 API 계약 수정:** SDK에 보내는 검색 옵션을 소문자로 정상화. 정확 검색이 실제로 불일치일 때만 정리된 건물/지번으로 기본 매칭을 추가하고, 반환 주소의 지역·도로/지번·건물번호가 일치해야 채택한다. API 오류를 검색 불일치로 숨기지 않는다.
2. **점진적 지도 표시 복원:** 성공한 마커를 현재 유형·반경 필터에 맞춰 즉시 추가한다. 기존에는 전체 주소 처리가 완료될 때까지 마커를 추가하지 않았다. 이 파일의 수정 전 고유 질의2,159개는 시작 간격150ms만으로 마지막 질의까지 최소5분24초가 필요했다. 이제 대기 중에도 확인된 위치를 볼 수 있다. 전체 완료 시 최종 집계·범위 맞춤은 유지한다.
3. **번지 형식 보완:** `동123-4`, `123-4번지`, `동(123-4)` 등 숫자가 있는 주소를 정리한다. `태평로1가`, 숫자가 들어간 `…로12길`, `…로123번길` 이름을 훼손하지 않는다. 동·구만 있는 주소와 다중 후보는 계속 보류한다.

환자·기록 수, 임상 유형·연령 계산, 통계 분모·반경 경계와 기존 지도 도구는 변경하지 않았다. 3.2.0 전체로 되돌리지 않았다. Worker·Secret 변경도 없다.
