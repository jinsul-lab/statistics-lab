# 환자 주소 입력·열 연결 독립 데이터 감사

검토일: 2026-10-04. 기준: JINSUL MAP v3.8.1, Git `a5dee1f`, `jinsulmap/jinsulmap.html`.

## 범위와 증거

현재 실제 의사랑·비트 출력 파일, 공급사별 공식 헤더 명세, 실제 주소 누락률은 제공되지 않았다. 아래 헤더는 문제 재현용 합성 사례이며 **해당 공급사가 이 형식을 사용한다는 주장이나 공급사 호환 인증이 아니다.** 환자 개인정보를 읽거나 외부로 전송하지 않았다. 주소 예시는 공공 도로명주소이며 차트번호·성명은 합성 값이다.

`work/emr_address_data_audit_v382.cjs`는 고정 기준 커밋에서 주소 처리 함수만 메모리로 읽어 13개 실패를 독립 재현한다. 온라인 주소 API 응답은 사용하지 않는다. `work/emr_address_xlsx_repro_v382.cjs`는 앱과 동일한 공개 SheetJS 0.18.5를 메모리에 내려받아 합성 XLSX를 생성·읽고 합성 CSV를 읽는다. 환자 데이터·결과 XLSX를 저장하지 않는다.

## XLSX·CSV 문자열 손실 재현

- 합성 XLSX 차트번호 셀: 저장 숫자 `123`, 화면 서식 `000000`. 기존 `sheet_to_json(...,{header:1})`은 `123`을 반환하고 `raw:false`는 표시 문자열 `000123`을 반환한다.
- 합성 CSV 차트번호 `000123`: 기존 `XLSX.read(text,{type:'string'})`이 숫자 `123`으로 바꾸고 `raw:true`로 읽으면 `000123`을 보존한다.
- `00123`과 `123`을 서로 다른 차트번호로 쓰는 파일에서 이 손실은 서로 다른 환자의 병합과 주소 충돌을 만들 수 있다. 공급사 실파일에서 실제 발생했다고 확인한 것은 아니다.
- 나이·신환 플래그의 기존 정책을 유지하면서 식별자 표시 문자열을 보존하고, 숫자가 필요한 항목에서만 명시적으로 변환하는 방식을 검증해야 한다.

[SheetJS 공식 배열 출력 옵션](https://docs.sheetjs.com/docs/api/utilities/array/)은 `raw` 기본값이 true이고 false면 서식 문자열을 사용한다고 설명한다. 실제 0.18.5 동작은 별도 합성 재현으로 확인했다.

## 안전한 주소 연결 기준

1. 파일 이름만으로 의사랑·비트 공급사를 단정하지 않는다. 시트·헤더 구조를 검증하고 자동 연결된 시트·식별자·기본주소·상세주소 열을 앱에서 보여준다.
2. 정확한 거주지 헤더를 우선한다. 우편번호, 보호자, 직장, 기관, 이메일은 주소라는 단어가 포함돼도 자동 거주지로 해석하지 않는다. 필요하면 사용자가 해당 열을 명시적으로 선택하게 한다.
3. 주소1·주소2, 시도·시군구·도로명·건물번호를 결합하되, 독립된 도로명·지번 두 전체 주소를 한 문자열로 무조건 붙이지 않는다. 상세 호수만으로 건물 좌표를 만들지 않는다.
4. 공백·줄바꿈·결측 표기만 정규화하고 원본을 보존한다. 도로명·본번·부번을 손상시키는 광범위한 숫자 제거는 금지한다. `정왕대로 210`과 `정왕대로 74`를 같게 취급할 수 없다.
5. 실제 주소 없음, 열 연결 오류, 후보 모호함, API 조회 실패, 지역은 있으나 정밀 좌표 없음은 원인이 다르다. 모두 `주소 미상` 한 상태로 집계하면 개선 효과를 측정할 수 없다.
6. 동일 환자 주소 충돌은 별도로 계수한다. 조회 성공 주소가 있다는 이유로 최근 주소라고 주장하지 않는다. 날짜·업데이트 기준일이 없으면 기존 첫 유효 주소 정책을 명시하고 검토 상태를 남긴다.
7. 동일 주소 조회의 중복 호출을 줄이고 일시 실패를 재시도하되, 짧은 지역명만 일치한 응답을 건물 단위 정확 주소로 확정하지 않는다.

## 필요한 실자료 검증

실제 공급사별 호환 확인에는 의사랑·비트 각각 **실제 헤더, 익명 차트번호, 가상 주소로 바꾼 소량 행**이면 충분하다. 실제 주민번호·성명·전화번호는 필요하지 않다. 자료가 없더라도 확인된 일반 파서 오류의 수리는 진행할 수 있지만 두 제품의 모든 출력 양식을 지원한다고 보고해서는 안 된다.

수리 후 검사에는 단순 성공률뿐 아니라 아래 수치를 따로 확인해야 한다.

- 주소 값 보유 고유 환자 / 전체 고유 환자
- 정밀 좌표 확인 / 주소 값 보유 고유 환자
- 행별 주소 대체·분리 결합으로 회복된 고유 환자
- 동일 환자 주소 충돌, 모호 응답, 일시 실패, 지역만 확인된 고유 환자
- 업로드 기록 수 및 임상 분류가 수리 전후 의도치 않게 바뀌지 않는지

지도 반경 분모는 좌표가 확인된 환자로 유지하고, 전체 환자 중 좌표 미확인 비중을 함께 표시해야 주소 누락이 지역별 수요 결론에 미치는 영향을 알 수 있다.

## 수리 후 독립 회귀

주 담당자의 최신 메인 HTML을 읽어 `node work/test_emr_address_import_v382.cjs`를 실행했다. **28개 검사 PASS, 실패 0개**다. 실제 의사랑·비트 파일의 인증을 뜻하지 않는다.

- 안내행과 실제 헤더 구분, 20행 이후 헤더, 거주지 주소·대체 지번·동명 헤더·우편번호/직장/보호자 제외.
- 주소1·주소2 결합, 시도·시군구·도로명·건물번호 결합, 시도 별칭의 중복 방지.
- 첫 `미상` 이후 유효 주소 회복과 충돌 오표시 방지, 실제 두 비어 있지 않은 주소 후보·충돌 보존.
- 주소2에 전체 주소가 있는 경우 회복 및 시군구 접두부 중복 방지; 상세 `101동 101호`만 있는 경우 좌표를 만들지 않음.
- 환자번호를 성명으로 사용하지 않음, 영문 헤더, 숫자 ID 0, 직접 주소 열 지정 버튼의 실제 재분석 및 기록 수 보존.
- 앱과 동일 SheetJS 0.18.5로 합성 XLSX를 생성·읽고 **실제 `processFile` 함수**에 전달: 표시 ID `000123` 보존, 문자열 ID `123`과 분리, 안내 시트·번호 요약 시트보다 주소 있는 환자 시트 선택.
- 같은 `processFile` 함수로 합성 CSV의 앞자리 0, UTF16LE·UTF16BE BOM TSV 처리 확인.
- 출처 메타데이터에 선택 시트명·행 수가 기록되고 원본 주소 값이 들어가지 않음, 주소 상태 계수 합계.

현재 회귀는 합성 파일·함수 호출 검증이다. 실제 EMR 내보내기 파일·공식 주소 API의 실제 응답·실제 브라우저 통합 검사는 주 담당자의 별도 근거와 구분한다. 앱 사용 중 확인된 실제 원주소 실패율을 아직 계산하지 않았다.
