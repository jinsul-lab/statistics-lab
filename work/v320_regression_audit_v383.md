# 3.2.0 → 3.8.2 주소 처리 회귀 대조

2026-10-24. 코드 검토와 공개 합성 문자열·모의 주소 API로 수행했다. 실제 환자 XLS는 이 하위 검토에서 열지 않았고, 실제 주소를 외부 API로 전송하지 않았다. 메인 HTML은 수정하지 않았다.

- 3.8.2: Git `5316202:jinsulmap/jinsulmap.html` (최근 주소 기능 변경).
- 재현: `work/v320_regression_audit_v383.cjs`. 소스는 Git에서 메모리로 읽으며 전체 HTML/내장 인증키를 출력하지 않는다.

## 모의 재현

8개 합성 형식 중 4개의 **번호가 있는** 형식이 3.8.2에서 요청 이전에 차단됨: `동123-4`, `동 123-4번지`, `동(123-4)`, 시도/구/동/번지 전체 붙임. 이들은 문자열 형식 검사의 회귀 증거이며 실제 API의 성공을 증명하지는 않는다. 도로명 붙임은 최신 코드가 일부 정상화하며, 동명만 있는 넓은 주소는 계속 보류되는 것이 적절하다.

EXACT를 ZERO_RESULT, 기본 매칭을 유일한 번지 응답으로 돌려주는 모의 API에서 최신 resolve는 SIMILAR 요청을 단 한 번도 시도하지 않고 unresolved로 종료함을 확인했다. 실제 서버의 두 모드 성공률은 이 검사에서 측정하지 않았다.

두 합성 환자 중 하나만 먼저 성공하고 다른 하나가 대기하는 상태에서 첫 환자의 marker는 존재하지만 clusterer 추가는0, applyFilter 호출도0이었다. 전체 batch 완료 후에만 applyFilter1회가 호출됐다. 이는 ‘처리 중 지도에 환자가 보이지 않는다’는 관찰과 일치하는 코드 경로다. 실제 첨부파일의 대기시간·완료 후 성공률은 부모 검토에서 별도로 다룬다.

## 최소 수정 제안

1. 공백 없는 번지·`번지` 접미사·숫자 괄호를 인식해 기존 숫자를 보존한다. 아파트 동/호·우편번호를 필지 번지로 잘못 해석하지 않는다.
2. 정확 매칭의 실패 뒤에는 기존 기본 매칭 후보를 검토할 수 있게 하되, 원문 시도/시군구·도로명/동·번지와 응답을 대조한다. 서로 다른 지역/필지 또는 광역 중심점은 환자 위치로 임의 채택하지 않는다.
3. 성공한 마커는 처리 중에도 현재 유형·반경 필터에 맞춰 점진적으로 표시한다. 통계 창 전체를 매 환자마다 재렌더하거나 사용자가 움직인 지도 범위를 매번 강제 변경하지 않는다.
4. 기존 최신 시간 초과·취소·중복 요청 통합·조회 실패/미상/반경 분모를 유지한다. 3.2.0 전체 코드로 되돌리면 이미 고친 집계/보안 결함을 재도입할 수 있으므로 주소 경로만 복원한다.

## 수정 후 독립 회귀 검사

주 담당자의 최신 인라인 함수에서 `work/test_address_recovery_v383.cjs` **18개 검사가 통과했다**. 실제 main HTML에서 함수를 추출하며 별도 이전 helper를 검증하는 것이 아니다.

- 숫자가 있는 공백 없는 번지·번지 접미사·숫자 괄호·전체 붙임 주소를 요청 가능 상태로 회복.
- `태평로1가`, `합성로123번길` 같은 숫자 포함 이름 보존.
- EXACT 이후 검증된 SIMILAR 후보 회복, SIMILAR 질의는 마지막 정리된 건물 주소1개만 사용.
- 다른 번지·다른 도로 건물번호·다른 시군구·동/도로 중심점은 환자 위치로 채택하지 않음.
- 서로 다른 좌표 후보는 미확인 유지, API 오류는1회 재시도 후 실패 유지.
- 나머지 작업 대기 중 첫 성공 마커 표시, 현재 유형·반경 필터 준수.
- 원래 환자·기록·유형 보존, 새 업로드로 취소된 작업의 늦은 마커 차단.
- SDK에는 소문자 `exact`/`similar`를 전송하고 내부 모드 표시는 `EXACT`/`SIMILAR`로 유지. 정확한 wire 계약을 강제하는 모의 API는 잘못된 대문자를 ERROR로 거절한다. 실제 소문자 변환을 제거한 변이 helper가 같은 검사에서 실패함을 확인해 이전 오류가 모의 응답 때문에 다시 통과하지 않도록 했다.

초기17개 검사는 모의 SDK가 대문자 모드도 수락했으므로 실제 SDK 요청값 오류를 탐지하지 못했다. 주 담당자의 실제 API 검사에서 `query.analyze_type should be exact,similar` 400 응답을 확인한 뒤, 이 하위 검토는 SDK 계약 검사를 추가하고 기존 모의 분기를 실제 소문자 값으로 수정했다. 따라서 초기 모의 성공을 실제 API 성공 근거로 사용하지 않는다.

이 검사도 합성 API 응답이다. 실제 카카오 서버의 매칭 성공률이나 실제 첨부파일 전수 좌표 정답률을 측정한 것은 아니다. `합성동산12-3`처럼 산번지가 동 이름에 붙은 추가 형식은 이18개 검사 범위 밖이며 주 담당자에게 별도 전달했다.
