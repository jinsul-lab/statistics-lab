# 환자 주소 통계 감사 · v3.8.2 작업

검토 관점: 통계 전문가. 기준: 수정 전 `jinsulmap/jinsulmap.html` v3.8.1. 실제 EMR·환자 자료는 제공되지 않았으므로 의사랑·비트의 모든 출력 형식, 실제 주소 성공률은 확인하지 않았다. 이 문서는 코드 추적과 독립 합성 입력으로 재현한 문제를 기록한다. 수정 후 검증 결과는 배포 보고서에서 별도로 구분해야 한다.

## 결론

기존 주소 지역·반경 통계는 **수정 필요** 상태였다. 주소 미상이 많다는 현상이 실제 주소 공란만 뜻하지 않는다. 원주소 공란, 변환 처리 중, 검색 결과 없음, API 오류, 콜백 미완료, 도로명 객체만 있는 정상 응답이 같은 지역 `미상`으로 합쳐진다. 반경 분석에서는 무좌표 환자를 먼저 제거하므로 그 화면의 미확인 수가 0으로 보일 수 있다. 산술 계산이 맞아도 선택된 모집단을 숨기면 대표성이 과장된다.

### 주소 반복과 호출량

기존은 환자마다 30ms 간격으로 검색하며 동일 주소도 반복 호출한다. 대량자료의 실행시간·오류와 호출량은 실측하지 않았으므로 실제 제한 초과를 입증한 것은 아니다. 코드상 중복 제거·동시 요청 제한·시간 제한이 없다는 점은 확인했다. 동일 정규화 주소의 응답 공유는 가능한 개선이며 원문과 행/환자 계보는 유지해야 한다.

## 독립 합성 기준값

`work/emr_address_statistics_audit_v382.cjs`는 Git HEAD의 v3.8.1을 읽어 수정 전 결함을 재현하는 forensic 테스트다. 개선 후 회귀 테스트와 성격이 다르므로 최신 HTML에 대한 통과로 보고하면 안 된다. 공개 주소나 실제 환자 주소도 사용하지 않고 완전 합성 문자열과 거리 stub을 사용했다.

독립 기대값:

- 고유 환자 **8명**, 업로드 기록 **14건**. 기존 집계 정책대로 동일 환자의 여러 행은 기록으로 센다.
- 정확좌표 확인 **4명(50%)**. 미확인 **4명**. 원주소 공란 1명과 주소가 있어도 좌표 미확인인 3명을 구분해야 한다.
- 1km 내 확인 환자 **3명**, 확인된 반경 밖 환자 **1명**, 위치 미확인으로 반경 판정 불가 **4명**.
- 반경 내 구성비는 확인된 환자 기준 **3/4=75%**. 전체 업로드 기준 확인된 반경 내 인원은 **3/8=37.5%**이며 나머지 4명이 반경 밖이라는 뜻이 아니다.
- 좌표 확인 거리 100,200,400,1500m → 평균 **550m**, 중앙값 **300m**. 미확인 환자를 0m로 포함하면 안 된다.
- 전체 신환 표기 표본은 A,B,C,E,F,G **6명**, 그중 반복 기록 B,C,E,G **4명 → 66.7%**.
- 1km 내 신환 표기 표본은 A,B **2명**, 반복 기록 B **1명 → 50%**. 작은 표본과 위치 선택을 보정한 결과는 아니다.
- 기존 코드의 지역 미상은 D,E,F,G,H **5명**. 실제 원주소 공란은 D **1명**이다. 이것이 사용자에게 주소가 있는데도 미상이 많아 보이는 한 재현 경로다.

테스트 실행 결과(수정 전): 위 모든 기대 산술을 확인했고, 로딩 미완료·도로명 지역 유실·반경 후 미확인0·마커 상태에 따른 0→3명 변화를 재현했다. 원인은 합성 응답 실험과 코드에서 확인한 것이며 실제 Kakao 서버 오류율을 측정한 것은 아니다.

## 수정 검증에 필요한 조건

1. 원주소 공란은 API에 보내지 않고 `missing`으로 종료한다. `ZERO_RESULT`와 `ERROR` 및 시간 초과는 다른 상태다.
2. 하나의 요청이 멈추더라도 전체 집계가 끝나고 실패 인원은 남는다. 최신 업로드 토큰과 리셋 토큰으로 이전 콜백이 새 환자와 통계를 덮어쓰지 않는다.
3. 동일 주소 공유 응답이어도 환자별 인원/기록 합계는 8명/14건을 보존한다.
4. 도로명 객체만 있는 성공 결과의 지역을 얻을 수 있으면 얻되, 행정동/법정동 근거를 유지한다.
5. 반경 필터 후에도 커버리지 표시는 반경 제외 이전 유형 집단에서 미확인 4명을 보존한다. 환자 표/분모는 확인된 반경 내 3명이고 판정 불가 인원은 별도다.
6. 클러스터 표시 여부를 바꿔도 반경 인원 3명은 불변이다. 유형을 끄면 실제 기준대로 합계가 변한다.
7. 주소 해석을 보완해 지역명에 원본 텍스트가 들어가는 경우 모든 표·툴팁·내보내기 HTML에는 escaping을 적용한다. 원주소에 HTML을 포함한 합성 입력도 코드로 실행되면 안 된다.
8. 원자료 형식의 정확성은 실제 비식별 의사랑·비트 예시 파일이 없으므로 미검증으로 남긴다. 벤더 이름만으로 열 순서나 데이터 의미를 확정하지 않는다.

## 범위와 한계

기존 방문기록 기반 신환/90일 분류 정책은 변경하지 않았다. 원본 중복방문 제거·날짜 기반 재방문 코호트·실제 거주지 검증도 수행하지 않았다. 이번 통계 감사는 주소 해석→좌표 상태→지역 묶음→반경 분모의 연결에 초점을 맞췄다. 실제 EMR마다 내보내기 메뉴·선택 항목·병원 설정이 다를 수 있어 검증용 원본 헤더와 비식별 표본이 확보돼야 벤더별 완료를 주장할 수 있다.

## 수정 후 독립 회귀 검증

`work/test_emr_geo_v382.cjs`는 **현재 실제 HTML의 인라인 함수**를 읽어 모의 API·타이머로 검증한다. 보조 helper 사본에만 의존하지 않는다. 2026-10-04 실행 결과 **49개 assertion 통과**:

- 일반 요청 3개 동시 처리 상한; 8명/동일 원주소 4개 입력에서 4회 호출; 환자 수는 8명 보존.
- 공란·번지 부족·검색 없음·API 오류·응답 시간 초과·다중 위치·잘린 응답·잘못된 좌표를 구분. 공란은 호출하지 않음.
- 오류 및 시간 초과는 1회 재시도 후 종료. 늦게 온 성공 콜백은 종료 상태를 덮어쓰지 않음.
- 도로명 객체만 있는 성공은 법정동 표시로 보존. 좌표→행정동 응답이 있으면 행정동 사용.
- 이전 업로드 콜백은 새 배치에 마커를 넣거나 완료 집계를 덮어쓰지 않음.
- 일부 실패와 일부 처리 중 상태가 공존하면 재시도 버튼 비활성; 모두 종료하면 실패 재시도 가능. 이로써 재시도로 토큰이 바뀌어 나머지가 영구 처리 중이 되는 경로 방지.
- 독립 8명/14기록 fixture: 좌표4명, 원주소공란1명, 검색불일치1명, 조회실패2명, 처리중0명. 1km내3명이고 반경 필터 후에도 커버리지 기준8명·미확인4명 제외 유지.
- 개별 마커가 클러스터로 감춰져도 반경 인원3명은 유지. 기존 분류를 끄면 실제 유형 기준2명으로 변경.
- 전원 주소공란 배치도 종료하고 빈 지도 bounds 이동은 하지 않음.

합성 API 응답·가속 타이머 결과이며 실제 Kakao API의 성공률·대량 자료 소요시간을 측정한 결과는 아니다. 3개 상한은 일반 응답 조건에서의 주소 처리 작업 및 정상 요청 동시성이다. SDK 요청 자체를 취소할 수 없는 시간 초과 상황에서는 이미 보낸 실제 요청이 서버에서 살아 있을 수 있으므로 물리 네트워크 요청 전체가 언제나 3개 이하라고 단정하지 않는다.
