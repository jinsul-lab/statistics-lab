# 첨부 XLS 로컬 입력 감사 · 2026-10-24

대상: 사용자가 제공한 `경로토탈.xls`. 파일은 로컬 메모리에서만 해석했다. 원본 사본·환자 행 스냅샷을 만들지 않았고 실제 환자의 이름/ID/주민번호/전화/주소를 출력하거나 외부 지오코딩에 보내지 않았다. 공개 SheetJS0.18.5 라이브러리만 내려받았다. 실제 주소 검색 성공률 검사가 아니라 **API 이전 입력 경로 감사**다.

`processFile`의 실제 Uint8Array/type:array 경로와 직접 SheetJS 해석→현재 parsePatients 경로가 모두2,397명·17,057기록으로 일치했다. 주소 열 선택이나 Excel 인코딩 때문에 대부분 주소가 사라지는 사례가 이 첨부파일에서 재현되지는 않는다. 행 수는 실제 방문일 중복 제거를 하지 않은 기록 수다.

API 이전 거절65명은 숫자 없는 주소47명과 숫자는 있으나 현재 번지/도로명 패턴에 맞지 않는 주소18명이다. 전체 원문은 유출하지 않고 형태 집계만 남겼다. 숫자 없는 불완전 주소를 임의의 지역 중심점에 환자로 표시해서는 안 된다.

## 지도 갱신 회귀의 직접 코드 증거

v3.8.2의 `patientAttachGeo`는 마커를 만들지만 클러스터에 추가하지 않는다. `patientStartGeocoding`은 모든 작업이 끝난 뒤 `applyFilter`를 한 번 호출한다. 따라서 좌표가 일부 확인되어도 전체 주소 처리가 끝나기 전까지 지도에 새 환자가 표시되지 않을 수 있다.

이 파일의 질의 생성 고유 주소는2,159개다. 시작 간격150ms만 고려해도 마지막 작업 시작의 이론적 하한은 `(2159-1)×0.15=323.7초`다. 이는 실제 완료시간 측정이 아니며 API 응답·대체 질의·역변환·재시도 대기는 별도다. 이 대기 동안 지도 갱신을 하지 않는 것은 사용자가 ‘주소 대부분이 안 찍힌다’고 느끼는 설명 가능한 직접 원인이다.

개선은 진행 중 적정 주기로 선택 유형·반경을 반영해 마커를 갱신하는 방식이 적절하다. 자동 화면 맞춤·통계 전체 재렌더를 매 주소마다 실행할 필요는 없다. API의 엄격한 EXACT 매칭과 구버전 비교는 별도 검증이 필요하며 이 입력 감사로 실제 검색 실패율을 단정하지 않는다.

## 재현

`node work/xls_real_import_audit_v383.cjs`는 로컬 원본을 읽고 스키마/집계만 출력한다. `setTimeout`에 등록된 지오코딩은 실행하지 않는다. 코드·검사 결과를 공개 저장소에 남길 경우에도 실제 원본·행·주소를 포함하지 않는다. 입력 파일이 달라지면 위 집계는 다시 산출해야 한다.

## 수정 중 최신 함수 재검사

주 담당자가 주소 문자열 경계와 진행 중 마커 표시를 보완한 뒤 실제 첨부파일로 로컬 입력 검사를 다시 실행했다. 전체2,397명·17,057기록·주소 있음2,376명·공란21명은 유지됐다. API 질의 생성은2,311→2,315명, 질의 이전 거절은65→61명(2.57%)으로 바뀌었다. 숫자 없는 불완전 주소47명은 그대로 보존하며 임의 좌표를 만들지 않는다. 숫자는 있지만 현재 패턴에서 거절되는 주소는18→14명이다.

이후 단계의 실제 API 매칭 여부는 주 담당자의 공개 장소 응답 검사와 구분한다. 이 검사는 실제 환자 주소로 API를 호출하지 않았으며, 자동 마커 표시 검증도 포함하지 않는다. 스크립트는 실행시각·HTML 코드 지문·실제 API 호출 카운터를 추가해 같은 수정본 재검사 여부를 확인할 수 있다.
